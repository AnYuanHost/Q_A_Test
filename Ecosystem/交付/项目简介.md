## 一、项目是什么

一个以 C++ 实现的**知识管理系统与推理引擎**内核：以集合论为底座，用"**零轮询机**"作为驱动知识执行的虚拟机，用"**解决方案**"对问答流图做子图替换，并在**描述逻辑**与**胡塞尔意向性**之上组织知识表示——是通往通用人工智能（AGI）的**符号推理**路线的工程实践。

## 二、要解决的问题

据设计资料，通往 AGI 的三条路线各有短板：联结主义（大模型）在哲学意义上的"通用"与知识可持续生产上不足；符号主义受既定规则束缚、泛化难达实用；非公理系统（NARS）理论不完备、到商业应用跨度过大。产业侧则以"**可信、可解释、可审计**"与"**降本增效**"为硬约束（详见《2.1 行业背景.docx》）。本项目主张：以确定性符号推理的**完备性**与**可解释性**承接这类需求。

## 三、技术路线与核心结构

| 概念（论文术语） | 作用 | 代码模块 |
|---|---|---|
| 元素—集合—映射 **E-S-M** | 最小原子，保障底层完备性与泛化 | `E_S_M` |
| 总元素环境检索器 **EES** | 符号表 / 语境 | `ESM_Manage` |
| **零轮询机**（虚拟机）、问答流图、轮询机 | 驱动逻辑执行与子图替换 | `Polling_Base` / `KRS_Base` |
| **解决方案**（子图替换 / 工厂 / 自举构建） | 把父问题分解为子问题 | `Solution` |
| **意向性知识图谱** | 意向性对象 / 管理器 / 超索引字典 | `Intentionality` |
| 数据/知识层 | 超索引落盘的知识单元、质性·质料双链知识库、解决方案脚本 | `KRS\`、`Obsidian\`、`KRS_Solution\*.lan` |

> 术语 ↔ 代码模块 ↔ 数据层的完整对照表见《项目手册.md》第〇章。

## 四、已建成的生态侧成果

- **内核控制台**（`app\`）：8 视图 Web 前端，**离线 / 实时双模式**；含内核概览、超索引库（搜索/排序）、解决方案（真高亮）、知识域、内核实测、脚本工作台、问答推演、项目台账
- **脚本常数支持**（解决"脚本语言连常数都没有"）：`const X = N;` 一键展开为内核可接受的节点序列（引擎 UMD 化，供控制台 / 插件 / 单测共用）
- **VSCode 插件 0.2.0**：`.lan`/`.pi` 语法高亮 + **实时校验** + **常数展开** + 格式化
- **工具链**：一键自检、离线快照生成、引擎同步、静态服务、案例矩阵实测脚本
- **文档**：项目手册 / 对接说明 / 行业背景 / 学术材料（原件 + 纯文本版）
