## 四、"逻辑"是怎么串起来的

```
编辑器输入 ──► WorkspaceStore（lan/pi）
                   │
                   ├─► 实时校验（LanToolkit）──► 问题面板 / 状态栏
                   ├─► flow-preview ──────────► 流图标签页（大纲选中可高亮）
                   ├─► script-diff ───────────► 版本数
                   └─► pi-helper / const-manager ─► 参数表 / 常数

命令面板（Ctrl/Cmd+K）
   └─► WorkspaceActions
         ├─ 选映射 → 插节点 → 补参数 → 校验 → 流图        （insertNode）
         ├─ 展开常数 → 补参数 → 格式化 → 校验 → 流图        （completeScript）
         ├─ 保存版本快照                                   （saveVersion）
         ├─ 当前脚本存为知识条目                            （saveKnowledge）
         └─ 推演当前脚本                                   （script-runner）
```

一句话：**任何跨插件的步骤，都收敛到 `WorkspaceActions` 的一条动作里**，界面只负责展示。

## 七、已知限制（如实说明）

- 插件与工作区联动**依赖 live 后端**（`node app/server/server.js`）；离线 `file://` 只有数据视图。
- `script-runner` 是**模拟推演**（按状态与分层），不执行真实内核。
- `kbase-write` 只写生态侧 `app/data/knowledge/`，**不直接改内核 `KRS`/`Obsidian`**；需要入库时用 `export` 人工确认。
- `flow-preview` 的边按"相邻层全连接"简化，细粒度依赖仍以 `.lan` 源码为准。
- 内核插件平台尚未就绪；当前插件是**生态侧**（前端 ↔ 插件），与内核插件接口通过 `/api/v1` 契约对齐。
