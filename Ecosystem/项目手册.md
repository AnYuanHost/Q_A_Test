## 〇、项目定位与参考资料

> 本节帮助接力者 / 评审快速建立正确认知。

**一句话定位**：以**集合论（E-S-M）** 为底座、以**零轮询机（虚拟机）** 驱动知识，理论根植于**胡塞尔意向性**与**描述逻辑（ALC）**，目标通往**通用人工智能（AGI）** 的知识管理系统与推理引擎。

**术语 ↔ 代码模块 ↔ 数据层 对照**（代码模块位于 `Lib.h.cpp\`，同名库位于 `Lib\`）：

| 术语 | 代码模块 | 说明 |
|---|---|---|
| 元素-集合-映射 **ESM** | `E_S_M` | 最底层框架（Element/Set/Map），整个工程建立其上 |

| 子元素环境检索器（字典序 / 8 比特 / 超索引） | 案例 `LexOrder_*`、`_8Bit_Sub_EES_*`、`SuperIndex_Sub_EES_*` | 分语境的信息检索器 |

### 1.2 核心项目：Q_A_Test 是什么

**"庞杂系统"（基于非公理化推理的问答内核）的教学/演示/测试项目**：C++ / MSVC / VS2026 的 Windows 控制台工程，内核以 **19 个预编译静态库 + 头文件** 形式提供（内核源码不在本仓库），理论根植于王培教授的 NARS 非公理化推理路线与胡塞尔现象学。

- 官方文档入口：`Doc\MD\MainMarkDown.md`（自称"庞杂系统 官方文档"）
- 配套课程：B 站 up 主 **WFW俱乐部**，`Course\Part 1\` 存放 PPT 与讲稿
- 许可证：LGPL 2.1
- 上游仓库：`https://github.com/AnYuanHost/Q_A_Test`（本地原为 ZIP 下载解压；现已在 `Q_A_Test-master\` 内 `git init` 并关联该仓库，见 ISS-04）

### 1.3 技术形态

- **语言/构建**：非托管 C++（命名空间 `Q_A`），x64 Debug，VS2026（Visual Studio Version 18）解决方案
- **架构**：内核各模块编译成独立静态库放在 `Lib\`，通过 `Lib.h.cpp\` 的头文件调用；链接方式为 vcxproj 的 `AdditionalDependencies` + 源码内 `#pragma comment(lib, ...)`
- **解决方案 `Q_A_Test.sln` 含 3 个项目**：
  1. `Q_A_Test` — 测试案例宿主（源码 `h.cpp\`，10 个可切换的 API 演示案例）
  2. `Execute` — 内核完整启动/执行器（`Execute\h.cpp\Main.cpp`，1356 行，完整启动流程）
  3. `Project1` — 空壳占位工程（仅 `int main() { return 0; }`，本身不完整）

### 1.6 运行机制（据 `Execute\Main.cpp`）

`InitializeEnvironment` → `InitializeSystemEnvironment`（装配 EES、KRSPDZ、AddressCreater、8Bit/Lex 子 EES）→ `LoadIntentionality`（从 KRS 文件读入字典与意向性管理器）→ `ConstructEnvironmentOrder` → `CompileExecuteFunction`（加载解决方案语言 → 编译 → 加载 → `ExecuteSolution` → `KRSPollingDrivenZeroRecursionMainFunction` 轮询主循环）→ 资源回收。硬编码超索引 **65576** 作为解决方案入口。

### 1.7 文档体系（`Doc\MD\`，601 个 md）

- `MainMarkDown.md` — 总入口（其链接的 `Q_A_Introduce.md` 本地缺失——ISS-06）
- `Lib_Introduce\`（580 文件）— 逐静态库 API 手册，入口 `Q_A_Lib_Introduce.md`
- `TextualMaterial\`（24 文件）— 理论文本：Part1 基础理论（非公理、意向性网络、集合论、问答论、智能体模型）、Part2 框架理论（ESM_Manage 框架）

### 1.8 KRS 数据是什么

- `KRS\` 下的编号 txt（如 `65540.txt`、`65576.txt`）**后缀是 txt，内容是二进制序列化对象**：文件名 = 超索引编号，文件 = KRS 按超索引落盘的知识单元
- `Data\KRS_Solution\SolutionBootstrap.lan` — 解决方案语言源码（文本，Hello World 级示例），`.pi` 为参数信息
- `Data\Obsidian\`（103 个中文 md）— Obsidian 知识库 vault，用"质性/质料"双链格式组织的中文知识图谱，是喂给 KRS 的词典/知识数据源
- `KRS_Base_Adam` / `KRS_Base_Eve` — 两套不同编号段的基库数据
- `运行快照\Deubg_Test\KRS\` 与仓库内 `KRS\` 路径完全一致、字节数差 330 → **是程序实际运行后写回的数据副本**

### 1.9 构建与运行

- VS2026 打开 `Q_A_Test.sln`，默认带一个无符号整型加法案例；生成错误时先检查包含目录（`Lib.h.cpp`）与库目录（`Lib`）能否检索到静态库
- 现成产物：`运行快照\Deubg_Test\x64\debug\Execute.exe`（内核执行器，2026-10-14 构建）、`Test.exe`（案例宿主）
- 产物内嵌 PDB 路径 `D:\AGI\Q_A\AI0001\...` → 由作者机器构建后拷贝过来
- ✅ **运行结论（2026-10-15 破案）**：exe 本身无问题。此前 `0xC0000005` 的根因是**运行时工作目录**——内核以相对路径 `..\..\KRS` 读知识库（相对进程 CWD 解析），且代码不检查 `OpenFstreamFunction` 返回值；把 CWD 设为 exe 所在 `x64\debug\`（**双击即满足**）后，对方 exe 与本机自建 exe 均完整运行。详见第六章 ISS-01

### 1.10 关键结论

1. **这是什么**：一个 C++ 非公理化推理内核（"庞杂系统"）的案例/测试仓库，内核本体以静态库二进制形式发布，本仓库提供头文件、演示案例、文档与数据。

### 3.2 正确运行方式（2026-10-15 破案结论）

- **内核 exe（Execute / Test）**：**CWD 必须 = exe 所在 `x64\debug\`**（**双击即满足**）。从其他目录用命令行启动会因相对路径 `..\..\KRS` 失效而以 `0xC0000005` 崩溃。
- **控制台前后端**：
  - 离线：双击 `app\web\index.html`（无需环境，自动用离线快照）
  - 实时：`node app\server\server.js` → http://localhost:3789
- **注意**：重启后端前先杀旧进程，避免 `EADDRINUSE`。

### 3.3 PowerShell 环境注意（本机踩坑固化）

- PS 5.1 不支持 `??`；无 BOM 的 UTF-8 脚本会被按 GBK 解析出错（需转 UTF-8 BOM）
- 探测外部命令须用 `cmd /c "..."` 并查 `$LASTEXITCODE`（`$ErrorActionPreference='Stop'` 下 git 的 stderr 会触发 NativeCommandError）
- `.NET` 文件 API 的相对路径不随 `Set-Location` 变化（须用绝对路径）

### ISS-01：Execute.exe / Test.exe 启动即崩溃（0xC0000005）（✅ 已解决，2026-10-15）

**结论（破案）**：exe 本身**没有任何问题**。崩溃根因有二：

1. **运行时工作目录（主因）**：内核用相对地址 `..\..\KRS\KRS_Base\*.txt` 读取知识库（实测打印地址证实），相对**进程 CWD** 解析。若 CWD 不是 exe 所在的 `x64\debug` 目录，`..\..\` 逃逸到不存在的路径 → 文件打不开。
2. **代码缺防护（真 bug）**：`OpenFstreamFunction` 返回 false 后代码不检查，继续执行 `FstreamReadIntentionalityObjectFunction` 读无效流 → 0xC0000005。

**证据链**：分段 printf 定位崩溃于 `LoadIntentionalityFunction` → 打印文件地址发现 `..\..\` 相对路径 → 打印 `OpenFstreamFunction` 返回值 = 0（失败）→ 改正确 CWD 后同一 exe 不再崩溃。

**给 AnYuanHost 的建议（原代码未改动）**：`LoadIntentionalityFunction` 检查 `OpenFstreamFunction` 返回值，失败时打印实际路径再退出，别以访问违规形式崩溃。

**遗留**：无（诊断 printf 已全部撤销，`Execute\h.cpp\Main.cpp` 已恢复原样）。

**历史诊断记录**：曾排除中文路径、缺 Debug CRT、缺依赖 DLL、命令行参数等假设；WER 定位故障模块为 exe 自身；10-14 晚证实"自建 Q_A_Test.exe 运行正常 → 非环境问题"，10-15 定位到 CWD 根因。
