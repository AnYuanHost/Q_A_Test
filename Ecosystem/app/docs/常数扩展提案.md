# 解决方案脚本语言 · 常数扩展提案

> 提案方：ChokingTea（前后端/生态）→ AnYuanHost（内核）
> 背景：2026-10-14 聊天「现在这个脚本语言连常数都没有」
> 现状：本提案的**生态层实现已在脚本工作台可用**（见 app/web/js/lan-toolkit.js），本文给出两条内核侧演进路线。

## 1. 问题

当前脚本表达「10」只能靠 `NewUIntElement`（初值 0）+ 手写 10 个 `UIntSuccessor` 节点：

```text
NewUIntElement          // ← 想要 10，先默默写 11 个节点
EmptyElement
UIntTen
TraUntractable
UIntSuccessor
UIntTen
UIntTen
TraUntractable
… ×10
```

脚本膨胀、可读性差、易写错（多一个少一个 Successor 无从察觉）。

## 2. 生态层现状（已落地，内核零改动）

脚本工作台支持声明式常数：

```text
const UIntTen = 10;
```

一键展开为内核可直接接受的等价节点序列，并自动补 `.pi` 参数行 `UIntTen UInt 10 Unlimited Login`。
展开规则：`const X = N` ⟹ 1 个 `NewUIntElement` + N 个 `UIntSuccessor`（依据 NewUIntElement.md / UIntSuccess.md 的定义域值域契约）。
引擎 `app/web/js/lan-toolkit.js` 为纯函数，可直接移植到 VSCode 插件或内核插件。

## 3. 内核侧演进路线（供选择）

### 路线 A：编译器字面量（彻底）

在 `Solution_Language` 编译器中支持值域为 UIntSet 的数值字面量节点：

```text
UIntLiteral
10
UIntTen
TraUntractable
```

或在参数表扩展数值绑定（`UIntTen UInt 10 …` 的第 3 字段本就是基础信息，可约定其为初值，由 `NewUIntElement` 读取）。
优点：脚本最简；缺点：动编译器 + 元素构造流程。

### 路线 B：预处理宏（渐进，改动最小）

内核加载 `.lan` 前增加一次文本预处理：识别 `const 名 = 整数;` 并做与本工作台完全一致的展开。
优点：编译器核心不动、与生态层行为一致（工作台展开结果可直接作为预处理输入回归测试）；缺点：仍是文本级方案。

### 建议

先 B 后 A：B 让脚本作者立刻获得常数体验，且引擎已有 28 项单测可作为回归集；待编译器重构时再升级为 A。

## 4. 兼容性说明

- `const` 语法是纯前置声明，旧脚本零影响；
- 展开产物只用 `NewUIntElement`/`UIntSuccessor` 两个现有映射，无新内核依赖；
- 大数值（>255）生态层默认拒绝展开并提示走内核原生方案（防爆图）。
