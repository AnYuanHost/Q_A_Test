# 意向性基础模型

***

## 胡塞尔的意向性

胡塞尔先生为现象学奠定了最坚实的基础，在其中填充了大量的关于意向性的种种观念。本文对这一部分的介绍主要来自于扎哈维对其的解读，而因为整个项目的道路选择直接建立在后现代的生态化观念系统建设的背景下，所以对意向性部分进行了重构。将会根据重构后和原模型的相同点和不同点进行介绍。

首先，重构仍然保留了质性和质料的区分。质性是意向性行为的决定部分，决定了对象间是如何指向的。质料则是对质性行为的信息补充，可以是一个具体的命题，也可以是一个对象。两者共同决定了简单意向性模型建立的信息基础。可以这么理解：质性决定了意向性行为是什么，质料则决定了意向性行为所发生的具体场景。

例如：我怀疑命题A是真的。“我”是意向性发起的对象，“命题A”可以看成是意向性指向的对象。“怀疑”这一行为是质性，“命题A是真的”是质料。但是，为什么说描述指向的对象时使用“可以”这一用词，这是因为这其实并不是一个简单的意向性。对于这一句话的意向性解读并不唯一，在引入更多的背景信息的情况下，这一句话事实上可以解读出不同的意向性结构。比如质性可以进一步细化为“怀疑命题是否为真”，这是质料便可以将命题所带来的信息剥离出去，只剩下“A”。而还需要注意的是，这两种解读方式中，质性和质料是不同的，而意向的对象也是不同的。

这在实际的应用中也指出一个很关键的问题，围绕意向性所建立的基础模型，掺杂了大量的各种观念，这导致了每个人都有自己的理解。底层的含混导致在很多时候，并不能针对实际的意向性实例展开有效的分析。一方面想要解决这些含混，需要将整个意向性体系中涉及到的各种概念的各个解释版本和其中的关系都分辨出来，这部分工作量很大。另一方面需要将具体案例所涵盖的各种意向性的模式全部分析出来，这需要从外界引入大量的各种领域的信息来辅助分析，这部分的工作量同样很大。

这些问题可行的解法只能是先将案例和所使用的意向性定义，尽可能的局限在一个足够简单的范围内。这就为重构指明了一个可以尝试的方向，并且最终得到了一个很关键的范畴观念。本文在重构部分会详细介绍步骤与概念的变化。

而作为现象学的意向性，并不止简单的结构上。针对于各种各样的意向性，具有不同特征的意向性，这些特征和分类才是现象学意向性的主要组成部分。这里的问题在于，因为这些掺杂的各种新的特征，几乎不能通过底层的模型去建立这些“上层建筑”。这个问题直接导致了在工程中想要系统的使用意向性时，没有办法在底层设计一个基本模型，然后再通过基本模型去做应用层的实际的意向性的呈现。

## 重构与模型建立

在上文对现象学的简单描述与剖析中可以得出结论，如果想要以可工程化的认识模型为目标，那么必须给出一个足够通用的意向性模型。所以，如何针对这个目标给出相应的改造，便是本节中重构和建立模型的重要组成部分。

重新来看意向性的例子，可以分离出这几个概念：意向性发起的对象，意向性指向的对象，意向性行为；质性，质料以及可能的额外的补充信息。接下来的重构便会围绕这几个概念的定义和定位进行展开。

首先，意向性发起的对象的范围需要进行拓展。传统现象学的意向性发起的对象一定是人，是人自身的意识才能支撑起意向性行为，进而显现出一个实际的意向性行为。但是考虑基础模型，需要将意识剥离出去。也就是说，需要将意向性模型还原到任何两个事物之间的关系，等到开始建立上层建筑时，再反过来引入意识来显现人的意向性行为。

那么为什么寻找更基础的解释，被称为拓展其范围呢？原因在于针对意向性的探索往往可以表述为：为一个新的意向性解释赋予新的特征。也就是说，通过向意向性集合中添加新的元素来拓展集合的范围。而寻找更基本的解释，则是希望直接在集合本身，确定其通用性涉及到的范围。比如确定一个足够有效的判断元素是否属于集合的方法。而这样则可以引出一个有效的方法：依靠通用性的相关方法，从应用方向寻找那些可以继承通用性的概念。

为了追求极致的通用性，意向性对象的范围先被拓展到极限。任何信息只要存在差异，那便是两个不同的意向性对象。换句话说意向性对象被期望用于显现所有的任何的差异。这赋予了意向性对象足够的通用性，但也将意向性本身的特征彻底消解。意向性对象是显现信息差异的工具，能够显现的范围则取决于显现方法本身。但是，需要注意，如此拓展，将意向性彻底的工具化，虽然享受到了通用性和解释的便利，但这也意味着连意向性中普遍出现的特征也被剥离出去，或者说，成为了通用性所支持的一种可能，而不再是意向性的本质。

这么做的另一个后果在于，意向性指向的对象这一概念产生了多个新的解释。在原本的解释中，指向对象是纯粹的对象，其范围和意向性发起对象没有任何区别，都将被工具化无限的拓展其通用性。而在其余的解释中，指向对象将被不同的应用方向赋予新的意义。例如，指向对象将会被整合到质性中，变成统一的部分。但是，所有的新的解释，都是包含于原本的解释的，这是因为工具化所带来的通用性并不是这些新的解释可以超越的。

而质性和质料的划分依然保持不变，但对其的解释将进行以下的调整。首先便是指向对象被整合到质性中，这同时也意味着质料不再承担包含指向对象的责任，而仅仅是对质性这一意向性行为的信息补充。而进一步的解释则牵涉到通用性所带来的更大范围，即我们必须承认一点，质性本身也可以作为意向性指向的对象。也就是说，意向性行为和指向对象的结合依然可以作为另一个意向性的指向对象。而质料作为补充信息，其范围仍然等价于意向性对象的范围。也就是说，这些概念的范围（对应的集合）并没有区别，而区分仅仅是工具在使用这些概念时赋予的，而它们本身是等价的。唯一需要注意的一点在于，因为质性需要受到意向性行为的束缚，其范围可能会远小于其他的几个概念。之所以使用“可能”来进行描述，是因为可能存在一些解释，这些解释可以为所有的意向性对象进行包装，从而使质性继承到通用性和范围。

总之，可以暂时给出这样一个范围：

<center>发起对象 = 指向对象 = 质料 ≥ 质性</center>

<p>

这个范围有一个足够优秀的潜力，以至于可以忽视其在使用中的其他问题。那就是在工程应用时，允许直接使用简介的数据结构来表达意向性，而不需要考虑那些庞杂的特征。当需要使用这些特征的时候，便可以使用基本的模型来构建更复杂的结构，通过这种结构来承载这些特征信息，从而将实际的意向性行为显现出来。这个优良品质直接决定了计算机工程化的可行性，也为意向性相关方法的自动化奠定了基础。

而这么设计仍然保留了胡塞尔意向性本身的一个关键特征，即意向性并不是二元关系，而是结合了质料这一补充信息的三元关系。这一点的关键在于，如果想要大规模的构建意向性并使用，那么便不能采用二元关系。因为计算机中已经存在了大量的围绕二元关系建立的理论和方法，例如其中典型的知识图谱。如果意向性模型在功能实现上和知识图谱的功能大量重合的情况下，很容易论证两者在数理结构上是等价的，意味着意向性并不能带来足够新颖的突破。

在数理结构上，以图论为基础去呈现这种意向性的基础模型的话，可以做以下的两种解读。第一种解读不将质料视作独立的节点，而是有向边的补充信息。在这种解读下，除了需要在边的数据结构上维护更多的信息之外，和传统有向图构建的知识结构并没有区别，这里也不过多赘述。重点是第二种解读：质性和质料是两个点，这意味着意向性行为将有三个点和两条边组成，而其中一条边需要和另外一条边绑定，也就是这两条边性质不同且不独立。这个特殊的图会有一些新的有意思的数理特征，可以在研究意向性关系的时候提供一些新的视角。

## 工程设计的引导

在模型重构中，一旦将涉及对象的范围锁定，将可以呈现其模型的结构确定，那么便可以直接指导工程设计如何完成相关模块。这一部分的具体设计会在[意向性相关工具](Intentionality_Tool.md)以及相关模块中继续展开。在本部分，仅仅阐述如何将这种指导和具体的设计进行结合。

如果基于图及其变种来完成模型的工程化，现有的数据库生态和知识图谱生态将是不错的选择，但是需要确定如何保证工程化后仍然可以保留意向性本身的特征，而不是单纯的数理结构。这里的关键点实际上已经提到过了，正如意向性发起对象和指向对象在范围上没有区别，其在意向性领域的区别则是领域内的方法赋予的。数据库工具和知识图谱工具也仅仅是显现意向性所使用的工具，真正赋予意向性特征的是围绕这些生态建立的独属于意向性的方法。虽然这个观点将底层模型和上层方法建设隔开，相对来说比较偏颇，但可以有效地帮助我们快速完成工程化的基础建设。

另一方面，工程化仍需要结合计算机领域本身的特征，这意味着哲学概念的特征需要受到计算机概念的约束。例如上文所强调的对象的通用性，其会受到计算机模型本身的通用性的约束，例如在很多无限问题上，并不能从计算机中得到相应的支持。在应用过程中，必须注意到这些基本的观念，在工程化的过程中会受到哪些束缚，发生哪些改变。如果有一套健全的项目工程管理工具的话，便可以监测这些工程化的过程以及前后变化。这将有利于哲学到应用的实践过程足够平稳。
