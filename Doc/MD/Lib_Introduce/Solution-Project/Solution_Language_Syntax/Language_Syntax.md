# 解决方案脚本语言语法

***

每一个解决方案都需要描述问答流图替换过程中，替换前的图结构以及替换后的图结构，这些信息都有解决方案主语言文件完成提供。在该文件中，需要提供基本的映射信息，定义域与值域参数信息，以及节点的状态信息。

***

## 图块

解决方案需要区分替换前问答流图与替换后问答流图，使用花括号对来分割图的区域。在实际编写时，并列两个花括号，表示前后图，按照以下写完完成：

```C++
{
    //替换前问答流图
}

{
    //替换后问答流图
}
```

***

## 并行子图

解决方案中一些子图可以并行操作，为了表示并行关系，使用方括号表示节点间存在并行关系。而且具有并行关系的子图和前置节点全连接，和后置节点全连接。

### 案例：

```C++

// Node 01

[
    // Node 02
]

[
    // Node 03
]

// Node 04

```

在案例中，节点1的后置节点是 节点2 和 节点3，节点2 和 节点3 并行，并且后置节点均为节点4.

***

## 节点

在问答流图中，每一个节点都需要提供基础的映射检索信息，定义域和值域参数的检索信息，以及需要补充的问答流图节点状态信息。其中，映射检索信息需要保证在智能体环境中的公共检索和私有检索以及静态库检索可以完成检索。参数检索信息需要保证可以在参数表中完成检索。而节点状态为固定值，有特定字符串来确定。

```C++
Map Information
( Domain Parameter )
( Range Parameter )
Node State
```

***

## 节点状态

节点状态有下面几种：

Tractable 可执行：节点可以分配轮询机并启动线程

Pending 等待：节点的前置节点均已执行完成，但需要等待

Untractable 不可执行：节点必须等待前置问题解决完成

TraUntractable 不可执行（特殊）：节点在前置节点全部完成后可直接转换成可执行状态

***

### 可执行状态

一旦节点进入可执行状态，意味着其前置节点全部完成执行，映射信息可以被唯一确定为一个原子映射，其所有参数信息均可以通过符号表唯一确定，且已经通过某些条件允许。条件允许指一些问答流图受条件调控，只有在满足条件时才允许进入可执行状态。

所以在一些子图替换中，可以看到映射和参数满足所有条件，且前置节点均运行完成的节点仍然需要等待。只有当外部条件通过时，才可以通过专门的子图替换替换为可执行状态并执行。而在没有外部条件，希望更快执行时，节点的状态会被设置为特殊的不可执行状态，该类节点在前置节点执行完成后不会进入等待状态，而是直接进入可执行状态。

***

### 等待状态

等待状态的节点仅仅满足前置节点全部执行完成，但是其本身仍然存在一些问题，例如并非原子映射需要进一步的子图替换，虽然是原子映射但扔需要外部条件再次调控等等。在问答流图的后推中，只要一个节点的前置问答节点全部执行完成，那么它便可以进入等待状态。只有部分特殊的节点可以直接进入可执行状态。

***

### 不可执行状态

不可执行状态指出节点的前置节点中必然有未完成的节点，必须等待前置节点执行。并且这些普通的节点在前置节点执行完成后也只会进入等待状态。

***

### 特殊不可执行状态

以Tra作为前缀的特殊不可执行状态，可以在前置节点完成执行后直接进入可执行状态，以方便图快速后推，减少询问次数。

***

## 参数结构

问答流图节点的参数以序列树的形式存在，每一个节点下并列的兄弟节点以小括号作为边界。

```C++
Parameter0
( Parameter1 ( Parameter2 Parameter3) Parameter4 )
```

***

## 简单案例：

```C++
{

}

{
    CMDPutHelloWorld
	EmptyElement
	EmptyElement
	Tractable
}
```
